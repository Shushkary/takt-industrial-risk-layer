# Технический регламент проекта

ТАКТ — аналитический и доказательный слой для расследования инцидентов на объектах АСУ ТП/КИИ.
Два трека одной платформы: промышленный (КИИ, ФСТЭК) и SOC для конкурса Positive Technologies
«Техлаб 2026» (см. [`docs/pt_techlab/README.md`](docs/pt_techlab/README.md)).

Этот файл — **технический регламент**: границы, контракты слоёв, правила сборки и эксплуатации.
Он источник правды для всего, что проверяется тестами и CI.

## Границы продукта — не нарушать

Полный текст: [`docs/product_boundary.md`](docs/product_boundary.md). Проверяются тестами и
release-gate. Кратко:

- ТАКТ **не выполняет** критичные действия автоматически: не блокирует, не изолирует, не
  останавливает ПЛК, не меняет конфигурацию оборудования, не закрывает инциденты без оператора.
  Пакет реагирования — **рекомендации**, исполняет их внешняя система после подтверждения аналитика.
- ТАКТ **не является СКЗИ**. Собственной криптографии в домене нет; ГОСТ/КЭП-подпись выполняет
  внешний сертифицированный сервис через инфраструктурный адаптер.
- В `src/takt/domain` запрещены криптография, сетевые вызовы, обращения к ОС, ORM, FastAPI,
  `pydantic_settings`. Контракт держит `import-linter` (конфигурация в `pyproject.toml`).
- В `src/takt/domain` запрещены источники недетерминизма: `datetime.now/utcnow`, `time.time`,
  `uuid.uuid4`. Время и идентификаторы — только через порты `SystemClockPort` / `IdProviderPort`.
  Сторож: [`tests/test_domain_ast_policy.py`](tests/test_domain_ast_policy.py).
- Никаких endpoint, кнопок или сценариев активного управления оборудованием в API и UI.

Если задача требует нарушить любой пункт — **остановись и спроси**, а не обходи.
Ослаблять сторожа ради зелёного прогона запрещено.

## Детерминизм контура вердикта

Воспроизводимость вердикта — основа юридической значимости доказательного пакета: повторный
прогон на тех же данных обязан дать тот же вердикт (`LEG` / `ILLEG` / `UNDET`), то же объяснение
и то же агрегированное контрольное значение манифеста.

Поэтому в `takt.domain` и `takt.application` запрещены сетевые вызовы, генераторы случайности
(`random`, `secrets`) и вызовы языковых моделей. Сторож:
[`tests/test_verdict_determinism_guard.py`](tests/test_verdict_determinism_guard.py).

ИИ-ассистент — вне обязательного объёма MVP. Допустим только изолированным опциональным модулем
вне контура вердикта; его вывод помечается как недоказательный и не входит в манифест и
агрегированное контрольное значение. Условия — [`docs/product_boundary.md`](docs/product_boundary.md),
раздел «Детерминизм вердикта».

## Алгоритмическое ядро под патентной защитой

Не менять без явной команды и пометки о сверке с формулой изобретения (заявка № 2026112859):

- формирование кейса: события + организационный контекст + сверка + триадный вердикт +
  контрфактическое объяснение;
- контур целостности доказательного пакета: контрольные значения элементов, канонический манифест,
  агрегированное контрольное значение, электронная подпись;
- машиночитаемая метка пригодности для процессуальных действий;
- движки `risk_engine.py`, `chaos_predictor.py`, `phase_time_tagger.py`, `xai.py`.

## Запуск и тесты

```powershell
python -m pip install -e ".[dev]"
python -m pytest
lint-imports                        # контракты слоёв
uvicorn takt.interface_adapters.api.main:app --reload --port 8090
```

Для вывода кириллицы в консоль добавляй `PYTHONUTF8=1`. Системный `python` в Git Bash на машине
разработчика может не содержать `pytest` — используй интерпретатор из окружения проекта.

Фронтенд (вспомогательный React-АРМ): `cd frontend/takt-arm && npm ci && npm run test:frontend`.

Полезные скрипты: `export_case_scenario.py`, `eval_detection.py`, `eval_correlation.py`, `verify_audit_ledger.py`,
`verify_operation_ledger.py`, `generate_sbom.py`, `release_finalize.py`, `build_release_package.py`,

## Правила разработки

- **Тесты — граница правды.** Новая логика: сначала тест, потом код. Если рефакторинг ломает тест —
  остановись и спроси, важнее поведение или структура. Не переписывай тест под сломанный код.
- **Инварианты домена неприкосновенны.** Прежде чем менять L1 — перечисли затрагиваемые инварианты
  и получи подтверждение.
- **Атомарные изменения.** Один коммит — одно осмысленное изменение; рефакторинг и новая
  функциональность не смешиваются.
- **Читаемость важнее краткости.** Код показывается интеграторам при сертификации: понятные имена,
  docstring на русском для доменной логики, типизация. Комментарии и документация — на русском.
- **Производительность — по измерениям.** Сначала профилировка, потом оптимизация. Прецедент:
  `InMemoryCaseStore.find_open_by_fingerprint` давал O(n²) и 21 минуту на бэктесте 100k событий —
  нашли измерением, а не догадкой.
- **Зависимости — под обоснование.** Каждая новая попадает в SBOM и становится риском при
  сертификации.
- Тесты обязательны для корреляции, поиска, формирования контекста и пакета реагирования
  (требование ТЗ). Регрессии качества детектирования ловит
  [`tests/test_detection_quality.py`](tests/test_detection_quality.py).
- Перед коммитом прогоняй релевантные тесты; перед сменой ветки проверяй, что работа идёт в `main`,
  а не в оставшейся feature-ветке.

## Два фронтенда — не перепутать

| Каталог | Роль | Стек |
|---|---|---|
| [`frontend/takt-pt-arm`](frontend/takt-pt-arm) | **Основной** АРМ аналитика | статический HTML/CSS/JS, без фреймворка |
| [`frontend/takt-arm`](frontend/takt-arm) | Вспомогательный | React + TypeScript + Vite |

Решение о выборе основного — от 2026-08-03, по итогам встречи с заказчиком.

### АРМ (`takt-pt-arm`) — три обязательных правила

1. **Правишь `app.js` или `styles.css` — обязательно пересобери:** `node build-production.mjs`.
   `index.html` подключает `app.min.js`, а не исходник, поэтому без сборки изменения просто не
   попадут на страницу. Артефакты (`*.min.*`, `index.prod.html`, `*.gz`) в git не хранятся.
2. **Поднимай параметр версии `?v=`** в `index.html` и `app.js` (формат `ГГГГММДД-NN`), иначе
   браузеры отдадут закэшированную сборку.
3. **При выкладке заливай `.gz` вместе с исходниками.** В nginx включён `gzip_static`: устаревший
   `app.min.js.gz` отдаст старый код при внешне успешной выкладке — ошибка выглядит как
   «изменения не применились».

### React-АРМ — публикация на подпуть

Базовый путь настраивается переменной сборки, маршруты в коде остаются относительными:

```powershell
$env:VITE_BASE = "/takt_pt/"; npm run build
```

Значение идёт в `base` (`vite.config.ts`) и в `basename` роутера (`src/main.tsx`). В Git Bash на
Windows такое значение подменяется на `/Program Files/Git/takt_pt/` — собирай в PowerShell. На
сервере подпуть требует SPA-fallback, иначе прямые ссылки дадут 404:
`try_files $uri $uri/ /takt_pt/index.html`.

## Одна редакция везде

Источник правды — этот репозиторий. Копии фронтендов, лежащие рядом на диске (`Version_3`,
`takt_pt_arm` в родительском каталоге), — исторические; правки веди в репозитории, иначе редакции
расходятся. Не редактируй файлы приложения напрямую на боевом сервере.

Выкладка на боевую ВМ выполняется **только с явного согласия владельца** и с предварительным
бэкапом (принята схема каталогов `*.pre-<метка времени>`).

## Данные заказчика и секреты

- Файлы от заказчика (схемы хранилища, датасеты, доступы к стендам) **в репозиторий не
  коммитятся** — они лежат вне рабочего дерева. Допустимы только производные: документация,
  коннекторы, синтетические фикстуры.
- Схемы PT NAD содержат пароли и ключи, восстановленные из трафика: `credentials[].password`,
  а также `account_password`, `case_sensitive_password`, `session_key`, `encryption_key` в
  запросах SMB и DCERPC. Коннектор
  [`nad_events.py`](src/takt/infrastructure/importers/nad_events.py) маскирует их по имени поля
  (рекурсивно, включая массивы) до записи в `payload`; при добавлении новых источников сверяйся
  со схемой стенда и расширяй `REDACTED_FIELD_NAMES`. Маскирование по фиксированному пути уже
  однажды пропустило пароль: в схеме стенда `credentials` — массив, а не объект.
- Секреты — только через переменные окружения, никогда в коде, логах и промптах ИИ. При ошибке
  разбора документа логируй путь и номер строки, а не содержимое.
- Не коммить: артефакты сборки, `dist/`, `.hermes/`, данные заказчика.

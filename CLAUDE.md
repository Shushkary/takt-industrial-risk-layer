# Инструкции по работе с проектом

ТАКТ — аналитический и доказательный слой для расследования инцидентов. Два трека:
промышленный (КИИ, ФСТЭК) и SOC для конкурса Positive Technologies «Техлаб 2026»
(см. [`docs/pt_techlab/README.md`](docs/pt_techlab/README.md)).

## Границы продукта — не нарушать

Зафиксированы в [`docs/product_boundary.md`](docs/product_boundary.md) и проверяются тестами:

- ТАКТ **не выполняет** критичные действия автоматически: не блокирует, не изолирует,
  не останавливает ПЛК, не закрывает инциденты без оператора. Пакет реагирования — это
  **рекомендации**, исполняет их внешняя система после подтверждения аналитика.
- В `src/takt/domain` запрещены криптография, сетевые вызовы, обращения к ОС, ORM и
  FastAPI. Контракт слоёв держит `import-linter` (конфигурация в `pyproject.toml`).
- Никаких endpoint, кнопок или сценариев активного управления оборудованием в API и UI.

Если задача требует нарушить любой пункт — остановись и спроси, а не обходи.

## Запуск и тесты

```powershell
python -m pip install -e ".[dev]"
python -m pytest                    # ~810 тестов, прогон около 4 минут
uvicorn takt.interface_adapters.api.main:app --reload --port 8090
```

На машине разработчика системный `python` в Git Bash может не содержать `pytest` —
рабочий интерпретатор: `C:/Users/Sasha/AppData/Local/Python/pythoncore-3.14-64/python.exe`.
Для вывода кириллицы в консоль добавляй `PYTHONUTF8=1`.

Фронтенд: `cd frontend/takt-arm && npm ci && npx vitest run` (45 тестов).

## Два фронтенда — не перепутать

| Каталог | Роль | Стек |
|---|---|---|
| [`frontend/takt-pt-arm`](frontend/takt-pt-arm) | **Основной** АРМ аналитика | статический HTML/CSS/JS, без фреймворка |
| [`frontend/takt-arm`](frontend/takt-arm) | Вспомогательный | React + TypeScript + Vite |

Решение о выборе основного — от 2026-08-03, по итогам встречи с заказчиком.

### АРМ (`takt-pt-arm`) — три обязательных правила

1. **Правишь `app.js` или `styles.css` — обязательно пересобери:** `node build-production.mjs`.
   `index.html` подключает `app.min.js`, а не исходник, поэтому без сборки изменения
   просто не попадут на страницу. Артефакты (`*.min.*`, `index.prod.html`, `*.gz`) в git
   не хранятся — они генерируются.
2. **Поднимай параметр версии `?v=`** в `index.html` и `app.js` (формат `ГГГГММДД-NN`),
   иначе браузеры отдадут закэшированную сборку.
3. **При выкладке заливай `.gz` вместе с исходниками.** В nginx включён `gzip_static`:
   если `app.min.js.gz` устарел, пользователи получат старый код при внешне успешной
   выкладке — ошибка выглядит как «изменения не применились».

### React-АРМ — публикация на подпуть

Базовый путь настраивается переменной сборки, маршруты в коде остаются относительными:

```powershell
$env:VITE_BASE = "/takt_pt/"; npm run build
```

Значение идёт в `base` (`vite.config.ts`) и в `basename` роутера (`src/main.tsx`).
В Git Bash на Windows такое значение подменяется на `/Program Files/Git/takt_pt/` —
собирай в PowerShell. На сервере подпуть требует SPA-fallback, иначе прямые ссылки
дадут 404: `try_files $uri $uri/ /takt_pt/index.html`.

## Одна редакция везде

Источник правды — этот репозиторий. Копии фронтендов, лежащие рядом на диске
(`Version_3`, `takt_pt_arm` в родительском каталоге), — исторические; правки веди в
репозитории, иначе редакции расходятся. Не редактируй файлы приложения напрямую на
боевом сервере.

Выкладка на боевую ВМ выполняется **только с явного согласия владельца** и с
предварительным бэкапом (принята схема каталогов `*.pre-<метка времени>`).

## Данные заказчика и секреты

- Файлы от заказчика (схемы хранилища, датасеты, доступы к стендам) **в репозиторий
  не коммитятся** — они лежат вне рабочего дерева. В репозитории допустимы только
  производные: документация, коннекторы, синтетические фикстуры.
- Схема PT NAD содержит `credentials.password` — пароли из трафика. Коннектор
  [`nad_events.py`](src/takt/infrastructure/importers/nad_events.py) маскирует это поле
  до записи в `payload`; при добавлении новых источников проверяй, нет ли в них
  аналогичных полей, и расширяй `REDACTED_FIELDS`.
- Секреты — только через переменные окружения, никогда в коде, логах и промптах ИИ.
  При ошибке разбора документа логируй путь и номер строки, а не содержимое.

## Стиль работы

- Комментарии и документация — на русском, как в остальном коде.
- Тесты обязательны для корреляции, поиска, формирования контекста и пакета
  реагирования (требование ТЗ). Регрессии качества детектирования ловит
  [`tests/test_detection_quality.py`](tests/test_detection_quality.py).
- Перед коммитом прогоняй релевантные тесты; перед сменой ветки проверяй, что работа
  идёт в `main`, а не в оставшейся feature-ветке.
- Не коммить: артефакты сборки, `dist/`, `.hermes/`, данные заказчика.

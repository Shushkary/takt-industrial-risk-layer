# ТАКТ — АРМ аналитика (основной интерфейс)

Статический АРМ без сборочного фреймворка: `index.html`, `styles.css`, `app.js`.
Решением от 2026-08-03 выбран **основным** интерфейсом проекта для «Техлаб 2026»;
React-вариант в [`frontend/takt-arm`](../takt-arm) остаётся вспомогательным.

Публикуется на `https://ralta.ru/takt_pt_arm/`.

## Разбор после автоматики

Интерфейс рассчитан на опытного аналитика, который получает инцидент **после**
отработки ML-контура, а не на первую линию. Экран расследования ведёт по шагам:

1. **Принято от автоматики** — сколько признаков закрыли правила SIEM и что
   осталось аналитику: инварианты вне SIEM, телеметрия технологического
   сегмента, связь нескольких классов источников корреляцией, хвостовой риск.
   Разбор автоматики **смоделирован** по охвату правил SIEM (`SIEM_COVERED_PREFIXES`
   в `app.js`); прямой интеграции с внешним ML-контуром нет, и в интерфейсе это
   указано явно.
2. **Обоснованность вывода** — одна величина вместо четырёх разбросанных признаков
   достоверности, с разложением по составляющим и их весам, и **маршрут добора контекста**
   («Чего не хватает»): какой документ нужен, у кого утверждается, за какое окно. Показатель
   приходит из `verdict_confidence` в ответе API — интерфейс его не пересчитывает, иначе
   значение в АРМ разошлось бы с тем, что уходит руководителю и в доказательный контур.
   Кнопка «Сводка для руководителя» открывает `GET /cases/{id}/decision-brief.pdf`.
3. **Гипотеза** — формулировка с точкой входа и целью плюс основания в данных.
4. **Почему это инцидент** — объяснение (XAI) по кейсу.
5. **Что отменит вердикт** — проверки, способные опровергнуть гипотезу.
6. **Уровни сущности** — адрес → узел → учётная запись → процесс → артефакт;
   переход по уровню открывает сущность и её baseline.
7. **Журнал находок**.
8. **Вердикт и выводы** — вердикт дублируется в шапке, чтобы оставаться видимым
   без прокрутки; варианты реагирования вынесены во вкладку пакета.

Время разбора считается от открытия расследования — это метрика заказчика
(сокращение времени на инцидент).

Варианты реагирования всегда предлагаются **списком с последствиями**, а не
единственным предписанием: критичные действия не выполняются автоматически,
решение принимает аналитик.

## Сборка

Артефакты (`app.min.js`, `styles.min.css`, `index.prod.html`, `*.gz`) в
репозитории **не хранятся** — они генерируются из исходников:

```powershell
node build-production.mjs
```

Скрипт минифицирует `app.js` → `app.min.js` и `styles.css` → `styles.min.css`
через `esbuild` (подтягивается `npx`), собирает `index.prod.html` со встроенными
стилями и готовит `.gz` для `gzip_static`.

> Раньше скрипт только упаковывал уже готовые минифицированные файлы, но не
> создавал их. Из-за этого правка в `app.js` могла не попасть на сайт: `index.html`
> подключает именно `app.min.js`. Теперь минификация выполняется здесь, поэтому
> исходник и то, что отдаётся пользователю, не расходятся.

JavaScript остаётся отдельным файлом и разрешён политикой CSP через
`script-src 'self'`; небезопасный `script-src 'unsafe-inline'` не используется.

При изменении кода поднимайте параметр версии `?v=` в `index.html` и `app.js` —
иначе браузеры продолжат отдавать закэшированную сборку.

## Данные

На ВМ интерфейс работает с REST API ТАКТ через `/takt_pt_arm/api/`. Очередь,
risk/impact/confidence, XAI, инварианты, KPI и контроль источников строятся из
реальных кейсов; обновление — раз в 10 секунд плюс живой канал `SSE`. Кнопка
принятия кейса использует штатные `lock` + `PATCH`.

При недоступном API интерфейс переходит на встроенный демонстрационный набор
кейсов, и блоки разбора продолжают заполняться — панели не остаются пустыми.

## Публикация

Файлы размещаются в `/var/www/ralta/takt_pt_arm`, а `nginx.takt-pt-arm.conf` —
в `/etc/nginx/snippets/takt-pt-arm.conf`. Сниппет подключается в оба server-блока
`ralta.ru` (HTTP и HTTPS).

Порядок выкладки, проверки и откат описаны в `DEPLOY_PROMPT.md` (вне репозитория).

> При обновлении обязательно заливайте `.gz` вместе с исходниками: `gzip_static`
> отдаёт `app.min.js.gz` при его наличии, и устаревший архив приведёт к тому, что
> пользователи получат старый код при внешне успешной выкладке.

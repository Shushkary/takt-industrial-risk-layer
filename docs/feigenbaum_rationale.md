# Обоснование инварианта «подозрение на period-doubling» (опрос ПЛК)

## Решение (Спринт 3)

Выбран путь **переименования и снятия научно-притязательной формулировки** в публичном API и каталоге, без заявления о «законе Фейгенбаума» как о физическом или статистически верифицированном свойстве конкретной сети.

## Что делает движок сейчас

В [`chaos_predictor.py`](../src/takt/domain/engines/chaos_predictor.py) используется **эвристика** по ряду интервалов опроса: из отношений соседних разниц строится коэффициент, который **сравнивается с эталонным числом 4.6692…** (известная константа в теории бифуркаций для класса отображений). Флажок «подозрение на кластер удвоения периода» выставляется, если отношение **близко** к этому числу (допуск по коду) и тренд разниц **возрастает**.

Это **не** доказательство хаотичности канала и **не** оценка по выборке с контролируемым FPR; это **сигнал для расследования** (MVP).

## Идентификатор и UX

- Публичный **`InvariantId`**: `polling_period_doubling_suspect` (вместо прежнего `polling_chaos_feigenbaum`).
- Описание в каталоге не ссылается на δ как на «закон» для промышленного трафика.
- В коде константа остаётся как **референсное число** для эвристики; при необходимости цель можно вынести в конфиг (`feigenbaum_target` в YAML).

## Дальнейшие шаги (вне текущего объёма)

Если понадобится **формализация**: явная модель отображения, эталонная выборка «без атак», статистический критерий (например, согласие распределений), целевой FPR — оформить отдельным ТЗ и версией инварианта; до этого поведение остаётся эвристикой с понятным именем и документом-раскладкой.

## Демонстрационный пакет для заказчика

Стенд, который заказчик разворачивает у себя, а не смотрит у нас. Собирается из
репозитория одной командой:

```powershell
python -m scripts.build_demo_package
```

На выходе — `dist/takt-demo-<версия>-<дата>.zip`: ядро ТАКТ, АРМ аналитика,
конфигурация Docker (API + сборщик инцидентов + nginx), демонстрационные данные
двух сценариев и инструкция на русском. У заказчика — `docker compose up -d --build`
и `docker compose run --rm seed`.

Исходники пакета — каталог [`demo/`](../../demo): `compose.yml`, `nginx.arm.conf`,
`README.md` (инструкция заказчику), `seed/seed.py` (засев).

Состав отбирается явно, а не архивацией каталога: документы выкладки с адресом
боевой ВМ и учётной записью (`deploy_ralta_current.md` и соседние) наружу не идут.
Сторож — [`tests/test_demo_package_contents.py`](../../tests/test_demo_package_contents.py):
он же ловит ссылку из пояснения АРМ, для которой в пакете нет документа.

Актуальный сценарий демонстрации — **INC-002** (компрометация конвейера сборки
через фишинг), см. [`docs/pt_techlab/prototype.md`](../pt_techlab/prototype.md).
Документы со сценарием «котельная» сохранены как история: они описывают
предыдущую версию стенда и метрику, снятую на нём.

Правило одной редакции: источник правды — этот репозиторий. Файлы приложения
не правятся напрямую на сервере, выкладка выполняется с явного согласия
владельца и после резервной копии.

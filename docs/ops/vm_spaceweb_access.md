# Доступ к ВМ SpaceWeb (ТАКТ)

Оперативная карточка доступа к боевой/стендовой ВМ. **Секретов здесь нет и быть не должно:**
пароли, 2FA-коды и приватные ключи хранятся вне репозитория (менеджер паролей / локальный диск).

## 1. Панель SpaceWeb (браузер) — reboot, VNC, сброс пароля

| Параметр | Значение |
|---|---|
| Панель | <https://mcp.sweb.ru/main/auth/> |
| Логин | `grflmailru` (аккаунт SpaceWeb) |
| Пароль | из менеджера паролей (в репозитории не хранится) |
| 2FA | SMS-код на привязанный телефон, запрашивается **на каждый вход** |
| Сессия | короткая: ~5 мин простоя → требуется перелогин |
| После входа | редирект на <https://vps.sweb.ru/main/> (облачный/VPS-раздел, **не** shared hosting) |

Навигация: «Виртуальные серверы» → строка сервера → карточка сервера (IP, статус, тариф, ОС).

- **Reboot** (если SSH не отвечает): «Перезагрузить» → «Подтвердить», ждать 60–120 с.
- **VNC-консоль**: «Перейти в VNC-консоль». Требует **пароль ОС**, не SSH-ключ. После харденинга
  парольная аутентификация отключена, поэтому VNC не пустит — сначала сброс пароля через раздел
  «Доступ» в панели или через `api.sweb.ru`.

## 2. SSH — основной способ

```bash
ssh -i ~/.ssh/id_rsa_spaceweb torionadmin@89.111.142.231
```

| Параметр | Значение |
|---|---|
| Хост | `89.111.142.231` |
| Пользователь | `torionadmin` (root отключён) |
| Аутентификация | только ключ; парольная отключена харденингом |
| Ключ | `~/.ssh/id_rsa_spaceweb` (резервная копия — на локальном диске оператора) |
| Привилегии | `sudo` доступен: `sudo systemctl status nota-api` и т. п. |

Если SSH ругается `REMOTE HOST IDENTIFICATION HAS CHANGED` (после переустановки/восстановления ОС):

```bash
ssh-keygen -R 89.111.142.231
```

## 3. Диагностика недоступного SSH

| Симптом | Причина | Действие |
|---|---|---|
| `Connection refused` | `sshd` не запущен (порт закрыт, но хост отвечает) | reboot из панели → `ssh … 'echo OK'` |
| `Connection timed out` | сеть/фаервол; VPS блокирует часть иностранного inbound | проверять с РУ-адреса; для посетителей сайта работает напрямую через DNS-only A-запись |
| ключ не принят | сброшена/переустановлена ОС, ключ не в `authorized_keys` | восстановление пароля и вход через VNC → вернуть ключ; сброс через панель «Доступ» или `api.sweb.ru` |

## 4. Что важно помнить

- Панель нужна ровно для трёх вещей: **reboot**, **VNC**, **сброс пароля ОС**. Всё остальное — по SSH.
- VNC бесполезен, пока парольная аутентификация выключена: сначала сброс пароля, потом консоль.
- DNS для публичного доступа держится в режиме **DNS-only** (A-запись без проксирования),
  иначе теряется прямой inbound для РУ-посетителей.

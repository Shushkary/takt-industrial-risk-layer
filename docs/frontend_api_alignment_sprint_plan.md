# Frontend API Alignment Status

Date: 2026-05-28

This document is now a status snapshot for the frontend audit alignment plan that was originally drafted on 2026-05-20. Frontend work must stay inside `frontend/takt-arm` in this repository. It must not use external local worktrees, absolute developer paths, or runtime dependencies outside this repository.

## Product Boundary

The ARM frontend must preserve the same product boundary as the backend:

- TAKT is an advisory industrial risk layer, not an active control system.
- The UI must not expose commands to stop PLCs, send commands to equipment, block accounts, disable nodes, or otherwise actively control industrial assets.
- Operator decisions, manual permits, evidence packages, audit ledger checks, and compliance views keep a human in the loop.
- Demo data must be explicit and must not be presented as working compliance evidence when a real API is configured.

## Completed Alignment

- API access is centralized through the TAKT ARM client under `frontend/takt-arm/src/app`.
- Runtime API configuration uses Vite environment variables rather than external local project paths.
- Zod validation is present for API response handling.
- Segment overview, incident queue, case detail, invariant library, topology map, and settings/audit screens are wired to the real backend API surface with explicit local demo behavior where needed.
- Operator workflows use backend endpoints for decisions, viewed/additional-review actions, manual permits, formal verdict history, evidence checklist, remediations, and readiness data.
- Frontend tests are present with Vitest and Playwright scaffolding.
- SBOM, CSP/nginx delivery assets, and CI scripts are present in `frontend/takt-arm`.

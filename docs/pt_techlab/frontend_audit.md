Дата: 2026-08-03. Объект аудита:

- **`/takt_pt/`** — React/TypeScript АРМ, исходники `D:\TAKT\TAKT PT\Version_3\app\frontend\takt-arm` (~6900 строк)
- **`/takt_pt_arm/`** — статический АРМ на ванильном JS, исходники `D:\TAKT\TAKT PT\takt_pt_arm` (~1300 строк)

Сам сайт с рабочего места аудита недоступен (HTTP и SSH к `89.111.142.231` отдают таймаут — ограничение сети), поэтому выводы построены на исходниках, конфигурации сборки, nginx-конфиге и сверке с бэкендом репозитория. Пункты, требующие проверки на самом сервере, отмечены явно.

## P0-1. Развёртывание на подпути сломано (React, `/takt_pt/`)

Три независимых признака указывают на одну причину — приложение собрано и написано так, будто живёт в корне домена.

**1. Сборка.** В `vite.config.js` отсутствует опция `base`. Итог в `dist/index.html`:

```html
<script src="/assets/index-CUXsrt2d.js">
<link href="/assets/index-BMLGm4xR.css">
```

Под адресом `/takt_pt/` браузер запросит `ralta.ru/assets/…` — то есть корень домена, а не каталог приложения. *Требует проверки на сервере:* если в nginx нет отдельного правила, отдающего `/assets` из каталога `takt_pt`, страница останется пустой.

**2. Сопоставление маршрутов.** `src/App.tsx` сравнивает путь целиком:

```js
const pathname = usePathname()          // под /takt_pt/ это "/takt_pt/incidents"
if (pathname === '/incidents') …        // никогда не совпадёт
```

Все семь маршрутов заданы без базового пути, поэтому под `/takt_pt/` любой адрес проваливается в ветку по умолчанию — «Обзор сегмента».

**3. Навигация.** Пункты меню в `AppShell.tsx` ведут на `/`, `/incidents`, `/search` и далее. `RouterLink` делает `pushState('/incidents')` — адресная строка становится `ralta.ru/incidents`, то есть пользователь уходит за пределы приложения. Внутри сессии экран отрисуется (после ухода из подпути сравнение внезапно совпадает), но обновление страницы или прямая ссылка приведут в никуда.

**Как чинить — заодно закрывая P2-1.** Вернуть штатный `react-router`, который решает всё это одной строкой:

```js
// vite.config.js
export default defineConfig({ base: '/takt_pt/', … })
```
```jsx
// main.tsx
<BrowserRouter basename={import.meta.env.BASE_URL}>
```

Маршруты и ссылки остаются относительными (`/incidents`), а базовый путь подставляется автоматически — при переносе на другой адрес правится только конфиг. Самописный `router.tsx` (81 строка) и связанные правки в `App.tsx` / `CaseDetail.tsx` удаляются, из-за чего исчезает и расхождение с репозиторием (P1-2).

## P0-2. Нет пакета реагирования (ТЗ §5.11, §14)

Поиск по всем экранам React-варианта не находит ни панели подготовки пакета реагирования, ни соответствующих вызовов API. Между тем ТЗ включает его и в функциональный контур (§5.11), и в перечень минимального результата MVP (§14): «подготовка пакета артефактов для реагирования».

В ванильном варианте `/takt_pt_arm/` он есть — по README, «пакет реагирования с обязательным подтверждением аналитика», что также корректно закрывает ограничение §6.3 о недопустимости автоматических критичных действий.

**Что сделать:** перенести панель в React-вариант (или, если ведущим станет ванильный, — оставить там). В любом случае экран должен формировать набор «тип артефакта — значение — узел — рекомендованное действие» и требовать явного подтверждения аналитика.

## P1-1. Два АРМ и два несовместимых контракта API

| | `/takt_pt/` (React) | `/takt_pt_arm/` (ванильный) |
|---|---|---|
| Объём | ~6900 строк, сборка Vite | ~1300 строк, без сборки |
| База API | `VITE_TAKT_API_BASE_URL` | `/takt_pt_arm/api/` → `127.0.0.1:18092` |
| Эндпоинты | `/cases`, `/cases/{id}/decision`, `/invariants` — как в репозитории | `/api/v1/cases`, `/api/v1/stream/cases` (SSE), `/api/v1/findings`, `/api/v1/baseline/…`, `lock` + `PATCH` |
| Живые данные | опрос по запросу | SSE-канал + обновление раз в 10 с |

Проверка по репозиторию: префикса `/api/v1`, эндпоинтов `stream/cases` и `baseline/…` в бэкенде **нет**. То есть варианты работают с разными бэкендами и не взаимозаменяемы.

**Что сделать:** зафиксировать один АРМ как основной, второй — либо удалить, либо явно пометить как дизайн-концепт (сейчас `takt_pt_arm/README.md` честно называет себя «вариантом дизайна», но при этом он развёрнут и ходит в боевой API). Держать два интерфейса с разными контрактами до конкурса — это двойная стоимость правок и гарантированное расхождение поведения на демонстрации.

## P1-2. `Version_3` разошёлся с репозиторием

Сверка с `takt-industrial-risk-layer/frontend/takt-arm`:

| Файл | Состояние |
|---|---|
| `src/App.tsx` | различается по существу (роутинг) |
| `src/pages/CaseDetail.tsx` | различается по существу (роутинг) |
| `src/app/taktApi.ts` | различается **только переносами строк** (CRLF против LF) |

То есть развёрнутая версия — форк, живущий вне git. Правила «одна редакция везде», принятого для другого проекта, здесь нет, и последствия те же: исправление в репозитории не доедет до сайта, а правка на сайте потеряется.

**Что сделать:** вернуть фронтенд в репозиторий как единственный источник (различие по роутингу исчезает само после P0-1), а расхождение по переносам строк снять через `.gitattributes` (`* text=auto eol=lf`).

## P1-3. Демо-данные теплоэнергетики в SOC-интерфейсе

`src/demo` — 657 строк, включая `heatEnergyDatabase.ts` (котельные, ЦТП, тепловые сети) и эмулятор телеметрии. Импорт есть **во всех семи экранах**, включая рабочие: очередь инцидентов, обзор сегмента, карточка, поиск, библиотека инвариантов, карта, настройки.

Для конкурса PT это чужая предметная область: жюри ожидает расследование киберинцидента SOC на предоставленном датасете (ТЗ §12.6), а не теплоснабжение Москвы — оно относится к промышленному треку продукта.

**Что сделать:** отделить демо-слой от рабочих экранов так, как это уже сделано в репозитории (режим `API` против `local-demo` по `VITE_TAKT_API_BASE_URL`), и для конкурсной сборки заменить датасет на выгрузку заказчика. Это одновременно снимает риск по compliance: демо-данные не должны попадать в рабочие отчёты.

## P2-1. Самописный роутер лишний

`src/router.tsx` реализует `usePathname`, `useNavigate`, `useSearchParams` и `RouterLink` — то, что `react-router` даёт из коробки, причём с поддержкой `basename`, которой здесь как раз не хватает. Дополнительно текущая реализация не обрабатывает `target="_blank"` и внешние ссылки в `RouterLink`.

Удаление даёт минус 81 строку своего кода, снимает P0-1 и восстанавливает паритет с репозиторием.

## P2-2. `CaseDetail.tsx` — 1342 строки

Это центральный экран по ТЗ §5.1, и в нём сосредоточено почти всё: обогащение, журнал находок, таймлайн, цепочка атаки, ручной наряд, доказательный пакет. Файл в 1342 строки для главного экрана — риск для скорости правок перед демонстрацией.

**Что сделать:** выделить блоки в компоненты (`EventFeed`, `EntityCard`, `FindingsJournal`, `AttackChain`, `ForensicPanel`) — механическая, безопасная декомпозиция без изменения поведения; тест `CaseDetail.test.tsx` уже есть и подстрахует.

## P2-3. Роли аналитика не видны в интерфейсе

ТЗ §5.13 требует разграничения прав первой и второй линии, руководителя и администратора. В бэкенде RBAC есть (`operator` / `auditor` / `admin`), во фронтенде упоминаний ролей нет — интерфейс одинаков для всех.

**Что сделать (минимально):** показывать текущую роль и скрывать действия, недоступные первой линии (по плану спринтов это ручная корректировка связей, merge/split и подтверждение пакета реагирования).

## Что в ванильном варианте сделано лучше — стоит перенять

Независимо от того, какой АРМ станет основным, эксплуатационная часть `takt_pt_arm` заметно зрелее, и её решения стоит перенести:

- **Корректная работа на подпути:** `location ^~ /takt_pt_arm/` с `try_files $uri $uri/ /takt_pt_arm/index.html` — SPA переживает перезагрузку и прямые ссылки.
- **Заголовки безопасности:** строгий CSP (`script-src 'self'`, без `unsafe-inline`), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`. У React-варианта аналогичной конфигурации нет.
- **Осознанные эксплуатационные решения,** зафиксированные комментариями в конфиге: буферизация выключена именно для SSE-канала и включена для обычного REST; динамический gzip отключён в пользу `gzip_static` с предсжатыми файлами — по следам реальной проблемы с зависанием `app.js`.
- **Живой канал очереди** через SSE вместо опроса.

## Порядок работ

1. **P0-1** — `base` в Vite + возврат `react-router` с `basename`; сразу закрывает P2-1 и половину P1-2.
2. **P0-2** — панель пакета реагирования (обязательна по ТЗ §14).
3. **P1-1** — решение по единственному АРМ; второй помечается концептом или удаляется.
4. **P1-2** — фронтенд обратно в репозиторий, `.gitattributes` на переносы строк.
5. **P1-3** — демо-слой отделить, датасет заменить на заказчика.
6. **P2-2 / P2-3** — декомпозиция `CaseDetail`, отображение роли.
7. Перенести на выбранный АРМ nginx-конфигурацию и заголовки безопасности из ванильного варианта.

## Требует проверки на сервере

Доступа к `89.111.142.231` из среды аудита нет, поэтому не проверено:

- отдаёт ли nginx `/assets` для `/takt_pt/` (от этого зависит, пустая страница там или рабочая);
- какой бэкенд слушает `127.0.0.1:18092` и совпадает ли он с кодом репозитория;
- совпадает ли развёрнутая сборка с `Version_3/dist` (нет ли ещё одной, третьей редакции).

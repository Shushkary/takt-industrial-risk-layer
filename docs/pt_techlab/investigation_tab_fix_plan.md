# План исправлений вкладки «Расследование» (АРМ `frontend/takt-pt-arm`)

Составлен по итогам аудита рабочего места аналитика от 2026-08-24. Основание — прогон на
стенде с датасетом INC-002 (1030 событий, 4 источника, 279 кейсов в очереди), а не чтение
исходников: все числа в плане измерены в браузере.

**Исполнитель:** модель Sonnet 5. План написан так, чтобы каждую задачу можно было выполнить
без дополнительных решений: указан файл, что менять, готовый текст/код и как проверить.

---

## 0. Как пользоваться планом

1. Читай раздел 1 целиком **до первой правки**. Там перечислены тесты, которые ломаются от
   безобидных на вид изменений в АРМ.
2. Задачи выполняются по одной, в порядке нумерации. Один коммит — одна задача (правило
   `CLAUDE.md`, раздел «Правила разработки»).
3. После каждой задачи: пересборка АРМ, прогон тестов из пункта 1.6, проверка на стенде по
   пункту «Проверка» самой задачи.
4. Если задача требует изменить домен (`src/takt/domain`) или ослабить guard-тест —
   **остановись и спроси**. В этом плане таких задач нет намеренно: всё, что нужно, уже отдаёт
   API.

## 1. Обязательные правила и ограничения

### 1.1. Пересборка после каждой правки

`index.html` подключает `app.min.js`, а не `app.js`. Без пересборки правка просто не попадёт на
страницу — и это выглядит как «изменения не применились».

```powershell
cd frontend/takt-pt-arm; node build-production.mjs
```

### 1.2. Параметр версии `?v=` и тест, который на нём завязан

Формат `ГГГГММДД-NN`. Значение обязано быть **одинаковым** в обоих местах `index.html`
(`styles.css?v=` и `app.min.js?v=`). Сейчас это `20260821-02`.

**Внимание:** `tests/test_arm_simulation_tab.py::test_cache_version_is_consistent_and_bumped`
жёстко проверяет `versions >= {"20260821-02"}`. При смене версии тест **упадёт** — это
ожидаемо: в том же коммите обнови ожидаемое значение в тесте. Версию поднимай один раз на
задачу или один раз на серию задач одного коммита.

### 1.3. Guard-тесты АРМ: что они запрещают

Три файла проверяют `index.html` / `app.js` / `styles.css` статически. Нарушение любого правила
роняет прогон:

| Тест | Что запрещено |
|---|---|
| `test_arm_russian_terms.py::test_arm_keeps_no_parallel_dictionary_of_statuses_or_sources` | Строки `TRIAGE`, `CONFIRMED`, `FALSE_POSITIVE`, `EXPECTED_BEHAVIOR`, `auth_logs`, `plc_polling`, `network_events`, `service_desk` в `app.js`. **Список статусов для смены строится из словаря `/catalog/vocabulary`, а не из литералов** |
| `test_arm_russian_terms.py::test_markup_has_no_latin_designations_left` | Видимый латинский текст в `index.html` (кроме `UTC` и `/simulation`). Новые подписи — по-русски |
| `test_arm_russian_terms.py::test_source_data_values_are_not_translated` | `term('operation'...)`, `term('protocol'...)`: значения источника не переводятся |
| `test_arm_simulation_tab.py::test_every_help_button_has_a_registry_entry` | Кнопка `data-help="X"` без записи `X` в `HELP` |
| `test_arm_simulation_tab.py::test_registry_has_no_unused_entries` | Запись в `HELP` без кнопки в разметке (исключения — `step`, `mitre`) |
| `test_arm_simulation_tab.py::test_simulation_view_declares_no_active_control` | Слова «Изолировать», «Заблокировать», «Выполнить», «Отправить команду», «Применить» внутри `#simulationView` |
| `test_arm_confidence_panel.py::test_arm_does_not_recompute_the_confidence_score` | Собственный расчёт обоснованности в АРМ: показатель только из `verdict_confidence` |
| `test_arm_confidence_panel.py::test_confidence_block_declares_no_active_control` | Активные глаголы исполнения в блоке обоснованности |
| `test_arm_simulation_tab.py::test_build_artifacts_are_not_committed` | `app.min.js`, `*.gz`, `index.prod.html` в git |

Формат записи `HELP` тоже проверяется регуляркой `^  ([a-z0-9_]+): \{$` — ключ с отступом в два
пробела, символы только `[a-z0-9_]`.

### 1.4. Границы продукта — не нарушать

- Никаких кнопок исполнения реагирования. Пакет реагирования (задача F-08) — **перечень
  рекомендаций с подтверждением аналитика**, без отправки команд куда-либо.
- В новых текстах сохраняется формулировка «ТАКТ не выполняет эти действия и не отправляет
  команды».
- Ничего в `src/takt/domain` этот план не трогает.

### 1.5. Чего в этом плане нет

Задачи не касаются вкладки «Симуляция», логики риска, движков и React-АРМ
(`frontend/takt-arm`). Единственное изменение вне АРМ — задача F-14 (новый endpoint сессии), и
она вынесена в конец с полным перечнем сопутствующих правок тестов и документации.

### 1.6. Прогон перед коммитом

```powershell
.venv\Scripts\python.exe -m pytest tests/test_arm_russian_terms.py tests/test_arm_simulation_tab.py tests/test_arm_confidence_panel.py tests/test_docs_canonical_arm.py -q
```

Для задач с бэкендом дополнительно: `tests/test_openapi_contract_snapshot.py`, `tests/test_api.py`.

## 3. P0 — до показа жюри

### F-01. Колонка «Основание» в цепочке событий

**Зачем.** И XAI-строка кейса, и подсказка «Как собран кейс» требуют от аналитика «отсеять
добранное расширением», но отличить такое событие в таблице нечем. При этом причина по
**каждому** событию уже приходит в том же ответе. Это же закрывает критерий ТЗ §12.2 —
качество корреляции должно быть видно пользователю.

**Данные.** `GET /cases/{id}/workspace` → `case.correlation_evidence[]`:

```json
{"event_id": "edr-0001", "rule": "pivot", "reason": "совпала отличительная сущность инцидента: user:smirnov", "fields": ["user:smirnov"], "manual": false}
{"event_id": "siem-0155", "rule": "host-expansion", "reason": "добрано расширением до уровня узла ws-17 в окне инцидента", "fields": ["host_id"], "manual": false}
```

**Файлы.** `frontend/takt-pt-arm/index.html`, `app.js`, `styles.css`.

**Что сделать.**

1. В `index.html`, в `<thead>` таблицы `.chain`, второй колонкой (после «Время, UTC») добавить:

```html
<th scope="col">Основание <button class="help sm" type="button" data-help="evidence" aria-label="Пояснение: основание попадания события в кейс">?</button></th>
```

2. В `renderCase` передать доказательства корреляции в `renderChain`:
   `renderChain(workspace.events || [], item.correlation_evidence || [])`.

3. В `renderChain` построить `Map(event_id → evidence)` и вывести ячейку. Названия оснований
   держать локально — это не обозначение из `vocabulary()`, а признак сборки кейса:

```js
// Основание попадания события в кейс. Значение приходит из `correlation_evidence` ответа API:
// свой вывод здесь разошёлся бы с тем, что уходит в доказательный пакет.
const EVIDENCE_RULE_RU = {
  'pivot': 'ядро',
  'host-expansion': 'расширение',
  'manual': 'добавлено аналитиком',
};

function evidenceCell(item) {
  if (!item) return '<span class="muted small">—</span>';
  const label = EVIDENCE_RULE_RU[item.rule] || item.rule;
  const kind = item.rule === 'pivot' ? 'core' : 'expanded';
  return `<span class="evidence ${kind}" title="${escapeHtml(item.reason || '')}">${escapeHtml(label)}</span>`;
}
```

4. Строки расширения приглушить: `.evidence.core` — цвет акцента, `.evidence.expanded` —
   `var(--muted)`; строка таблицы получает класс `row-expanded` с `opacity: .75`, чтобы ядро
   читалось первым.

5. Над таблицей — переключатель `<label><input type="checkbox" id="coreOnly"> только ядро</label>`
   и счётчик: «Показано N из 41 · ядро 25 · расширение 16». Числа считать по данным.

6. Запись `HELP.evidence` — готовый текст в разделе 6, запись 1.

**Проверка.** INC-002: 25 строк «ядро», 16 «расширение»; наведение показывает полную причину;
галка «только ядро» оставляет 25 строк, счётчик пересчитывается.

### F-02. Сброс выбранной сущности при смене кейса (дефект целостности)

**Зачем.** `openCase()` не трогает `selectedEntity`. Проверено на стенде: после перехода с
INC-002 на другой кейс панель «Сущность» продолжает показывать `ws-17`, кнопка «Добавить в
находки» активна — и запишет сущность **чужого кейса** в текущий, с записью в append-only
журнал. Для продукта, который продаёт доказательную целостность, это дефект первого приоритета.

**Файл.** `app.js`, функция `openCase`.

**Что сделать.** В начало `openCase`, сразу после `selectedCaseId = caseId;`:

```js
  // Сущность принадлежит кейсу, из которого её открыли: при смене кейса панель очищается,
  // иначе «Добавить в находки» запишет в новый кейс сущность из прежнего.
  resetEntityPanel();
```

Рядом с `openEntity`:

```js
function resetEntityPanel() {

```

### F-03. Карточка сущности в поле зрения и подсветка выбранного

**Зачем.** Измерено: клик по узлу в 30-й строке цепочки обновляет панель, которая в этот момент

**Файлы.** `styles.css`, `app.js`.

```css
.panel.side {

  max-height: calc(100vh - 24px);
  overflow: auto;

@media (max-width: 1200px) {

```

2. В `openEntity` — прокрутка на узкой раскладке и подсветка всех вхождений сущности:

```js
  // На одноколоночной раскладке карточка уезжает вниз страницы: без этого клик

  if (window.matchMedia('(max-width: 1200px)').matches) {

```

3. `.entity-link.active` — заметный фон. Подсвечиваются **все** строки, где участвует сущность,

### F-04. Таблица цепочки: своя прокрутка, липкая шапка, читаемые значения

**Зачем.** Измерено на 1440×900: таблица шириной 1620 px в колонке 751 px — 869 px (колонки
«Адрес» и «Артефакт») за горизонтальной прокруткой. Шапка задана `sticky`, но не липнет:
`.panel { overflow: hidden }` делает панель scroll-контейнером, который сам не прокручивается, и
после десятой строки заголовки уезжают. Контрольная сумма выводится целиком (64 знака,
`nowrap`), скопировать её нельзя.

**Файлы.** `styles.css`, `app.js`.

**Что сделать.**

1. Дать таблице собственную область прокрутки — это чинит и липкую шапку, и высоту страницы, не
   трогая `.panel`:

```css
.table-scroll {
  max-height: 60vh;
  overflow: auto;           /* было: overflow-x: auto */
}
```

`table.chain th` уже `position: sticky; top: 0` с фоном — внутри нового контейнера это
заработает.

2. Длинные значения усечь по центру, полное — в `title`, по клику копировать:

```js
// Контрольная сумма в 64 знака растягивает таблицу вдвое. Полное значение остаётся
// в подсказке и копируется по клику: аналитику оно нужно целиком, но не на экране.
function shorten(value, keep = 12) {
  const text = String(value ?? '');
  return text.length <= keep * 2 + 1 ? text : `${text.slice(0, keep)}…${text.slice(-keep)}`;
}

function copyable(value, label) {
  if (!value) return '';
  return `<button type="button" class="copyable" data-copy="${escapeHtml(value)}" title="${escapeHtml(value)}">${escapeHtml(label ?? shorten(value))}</button>`;
}
```

Обработчик — один на документ, рядом с обработчиком `data-help`:

```js
  const copyButton = event.target.closest('[data-copy]');
  if (copyButton) {
    navigator.clipboard.writeText(copyButton.dataset.copy).then(
      () => toast('Значение скопировано'),
      () => toast('Скопировать не удалось: буфер обмена недоступен')
    );
    return;
  }
```

3. Показывать **все** артефакты события. Сейчас `firstArtifact` берёт `artifacts[0]` — у 16
событий из 41 остальные скрыты молча:

```js
function artifactCell(event) {
  const items = event.artifacts || [];
  if (!items.length) return '';
  const first = `${term('artifact_type', items[0].type)}: ${copyable(items[0].value)}`;
  return items.length > 1 ? `${first} <span class="muted small">и ещё ${items.length - 1}</span>` : first;
}
```

Полный перечень — в `title` ячейки. Функцию `firstArtifact` удалить, чтобы не осталось второго
способа показать артефакт.

4. Адрес выводить через `copyable` (карточки для адреса API не отдаёт — см. F-06).

**Проверка.** Таблица укладывается в колонку на 1440 px; шапка липнет; клик по контрольной сумме
даёт тост «Значение скопировано»; у события с двумя артефактами видно «и ещё 1».

### F-05. Очередь: фильтры, лимит, сохранение фокуса

**Зачем.** На датасете 279 кейсов, 262 из них — «низкий» с одинаковым баллом 0.289 и
заголовками вида «Риск низкий: PROCESS_START». Всё это рисуется целиком и перезапрашивается
каждые 15 с (107 КБ на опрос ≈ 25 МБ/час на рабочее место). Измерено: при опросе фокус
клавиатуры уходит на `<body>`. `GET /cases` поддерживает 28 фильтров, сортировку, `limit/offset`
и отдаёт `X-Total-Count` — интерфейс не использует ничего.

**Файлы.** `index.html`, `app.js`, `styles.css`.

**Что сделать.**

1. В панель очереди добавить строку фильтров (подписи по-русски — правило 1.3):

```html
<div class="queue-filters">
  <input id="queueSearch" type="search" placeholder="поиск по заголовку или активу" />
  <select id="queueRisk"><option value="">любой класс</option></select>
  <select id="queueStatus"><option value="">любой статус</option></select>
  <button class="help sm" type="button" data-help="queue_filters" aria-label="Пояснение: фильтры очереди">?</button>
</div>
<p id="queueCount" class="muted small pad">—</p>
```

Варианты в `#queueRisk` и `#queueStatus` заполняются **из словаря** после `loadVocabulary()`
(`vocabulary.risk_class`, `vocabulary.case_status`). Литералов кодов в `app.js` быть не должно.

2. Научить `api()` отдавать заголовки ответа (`X-Total-Count`) — отдельной функцией
   `apiWithHeaders`, чтобы не менять поведение существующих вызовов.

3. `refresh()` собирает запрос `/cases?sort=risk_score_desc&limit=100` плюс `risk_classes`,
   `status`, `title_contains` из фильтров. `#queueCount` показывает «показано 12 из 279». Поиск —
   с задержкой 300 мс после ввода, изменение любого фильтра запускает `refresh()`.

4. Убрать лишнюю перерисовку и восстановить фокус:

```js
// Перерисовка неизменившейся очереди раз в 15 с сбрасывала фокус клавиатуры на body:
// пройти список с клавиатуры было невозможно.
function queueSignature(items) {
  return items.map((item) => `${item.case_id}:${item.status}:${item.risk_score}:${item.event_count}`).join('|');
}
```

В `renderQueue`: совпала сигнатура — выйти, ничего не трогая. Иначе запомнить
`document.activeElement?.dataset.caseId`, перерисовать, вернуть фокус на кнопку с тем же
`data-case-id` (атрибут добавить кнопке очереди).

5. Запись `HELP.queue_filters` — раздел 6, запись 2.

**Проверка.** Фильтр «средний» оставляет 17 кейсов, счётчик «показано 17 из 279»; поиск
«конвейер» находит INC-002; фокус на элементе очереди переживает опрос (подождать 20 с, нажать
Tab — фокус остался в списке).

### F-11. Карточка сущности: окружение, честная историчность, причины качества данных

**Зачем.** Три проблемы в одном месте.

1. **Окружение не выводится.** API отдаёт `environment` (до 100 последних событий сущности) и

3. **`dq_reasons` не показаны**, при этом метрика может показать «(неполные)» без объяснения.

**Что сделать.**

1. Строку «Историчность» переименовать в «Частота в истории»: `первое появление` /
   `редко: менее 3 событий` / `часто: 3 и более событий (29)`, рядом — `typicality.explanation`.

   другое.
2. Блок «Окружение»: последние 10 событий сущности (время, источник, операция) и строка «всего в
   истории: `environment_total`». Активность по часам (`activity_by_hour`) — опционально.
3. Под метрикой «Качество данных» выводить `dq_reasons`, когда список непуст; пометку

**Проверка.** Карточка `ws-17`: «часто: 3 и более событий (29)», окружение — 10 строк, «всего в

2. Значение приходит из ответа продукта (`correlation_evidence`), интерфейс его не вычисляет.
   Полная причина — в подсказке при наведении.
3. Что делать: разбирать сверху вниз ядро, а расширение отсеивать. Вместе с расширением в кейс
   попадает штатная активность тех же узлов — это цена полноты, а не ошибка сборки.

**Запись 2 — `queue_filters` (новая, F-05)**

Заголовок: «Фильтры очереди».

1. Отбор выполняет продукт, а не браузер: параметры уходят в запрос списка кейсов, счётчик
   показывает, сколько кейсов подошло под фильтр из общего числа.
2. По умолчанию показываются первые 100 кейсов по убыванию балла риска.
3. Что делать: начинать смену с фильтра по классу риска и статусу «новое». Поток однотипных
   одиночных срабатываний с одинаковым баллом — материал для правки правила, а не для разбора
   поштучно.

**Запись 3 — `response` (замена, F-08)**

Заголовок: «Варианты реагирования».

1. Действия, применимые к отличительным сущностям кейса: изоляция узла, сброс учётной записи,
   блокировка адреса, заморозка конвейера. Узлы, добранные расширением, показаны отдельной
   группой и по умолчанию не отмечены: они попали в кейс по узлу, а не по признаку атаки.
2. Перечень строится по артефактам кейса с признаком отличительной сущности.
3. Что делать: отметить применимые пункты и подтвердить пакет. Подтверждение записывает состав
   пакета в журнал кейса и готовит текст для передачи ответственному. ТАКТ не выполняет эти
   действия и не отправляет команды — исполняет внешняя система после решения аналитика.

**Запись 4 — `journal` (новая, F-09)**

Заголовок: «Журнал действий по кейсу».

1. Все действия, изменившие состояние кейса: сборка, находки, подтверждение пакета, смена
   статуса. В записи — время, автор и суть действия.
2. Журнал append-only и связан цепочкой хэшей: изменить прошлую запись нельзя, целостность
   проверяется отдельно по кнопке.
3. Что делать: передавая смену, ссылаться на журнал, а не пересказывать сделанное. По нему же
   считается сокращение ручных действий.

**Запись 5 — `entity` (замена, F-11)**

Заголовок: «Карточка сущности».

1. История и окружение выбранной сущности по всем принятым событиям, а не только по событиям
   кейса: когда впервые и последний раз встречалась, из каких источников, в каких кейсах
   участвует и что происходило вокруг.
2. «Частота в истории» — счётчик событий, а не модель поведения: «часто» означает три и более
   событий в накопленной истории и сам по себе не говорит, что активность нормальна.
3. Что делать: смотреть окружение и связанные кейсы. Если сущность встречается впервые или
   редко, событие в кейсе весит больше.

**Запись 6 — `dq_score` (дополнение, F-11)**

Заголовок: «Качество данных».

1. Доля признаков, вычисленных по событиям кейса без пропусков: 1.00 — данные полные. Пометка
   «(неполные)» означает частичную наблюдаемость; причины перечислены под значением.
2. Причины приходят из ответа продукта (`dq_reasons`).
3. Что делать: значение ниже 1.00 — причина запросить исходные журналы, а не понизить значимость
   инцидента. Неполнота снижает обоснованность вывода, но организационный документ не заменяет.

## 7. Порядок коммитов

Один коммит на задачу, сообщение по-русски:

```
fix(arm): сущность сбрасывается при смене кейса — находка не уходит в чужой кейс
feat(arm): в цепочке видно основание — ядро или расширение
feat(arm): карточка сущности не уезжает из поля зрения
fix(arm): шапка цепочки липнет, длинные значения не растягивают таблицу
feat(arm): фильтры очереди и сохранение фокуса при опросе
docs(arm): пояснения приведены в соответствие с интерфейсом
```

Версию `?v=` поднять в **последнем коммите каждой серии**, которая меняет `app.js` или
`styles.css`, и в том же коммите обновить `tests/test_arm_simulation_tab.py`. Формулировка
«один раз на серию P0» в первой редакции плана привела к тому, что все семь коммитов P1 вышли
под версией серии P0: браузер, открывавший страницу во время P0, продолжал отдавать
закэшированную сборку и ни одной правки P1 не показывал. Артефакты сборки (`app.min.js`,
`*.gz`, `index.prod.html`) в коммит не попадают — это проверяется тестом.

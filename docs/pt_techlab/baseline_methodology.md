# Методика измерения базовой линии расследования

Статус: проект v0.1. Цель — воспроизводимо проверить сокращение времени и ручных действий не менее чем на 30% относительно текущего процесса.

## Метрики

`T` — активное время расследования от открытия первого сигнала до фиксации решения аналитиком, без заранее объявленных пауз и ожидания внешнего ответа. Единица — секунда. `A` — число ручных действий:

- клик или подтверждение, меняющее состояние/представление;
- переключение между системами или вкладками разных систем;
- ручной ввод либо копирование идентификатора, адреса, хеша или фильтра;
- ручной запуск поиска, обогащения, экспорта или шага реагирования.

Прокрутка и чтение без изменения состояния не считаются. Серия набора одного значения считается одним действием. Автоматические операции не считаются ручными.

Для каждой пары прогонов:

`reduction_T = (T_current - T_TAKT) / T_current * 100%`

`reduction_A = (A_current - A_TAKT) / A_current * 100%`

При нескольких аналитиках публикуются медиана и диапазон; критерий выполнен, когда медианное сокращение целевой метрики не менее 30%, а исходные наблюдения доступны для проверки.

## Парный протокол

1. Зафиксировать версию датасета, сценария, систем, оборудования, сети и инструкций; очистить кэши между прогонами.
2. Выбрать минимум три репрезентативных инцидента и минимум трёх аналитиков. Порядок `current/TAKT` чередовать, чтобы снизить эффект обучения.
3. Выдать одинаковую стартовую информацию и критерий завершения. Наблюдатель запускает таймер при открытии первого сигнала.
4. Для режима `current` наблюдатель ведёт журнал времени и действий с записью экрана/событий систем, не подсказывая участнику.
5. Для режима `TAKT` источником истины служит append-only audit ledger: `actor`, UTC-время, тип действия, объект и correlation/request id. Начало и завершение отмечаются отдельными событиями эксперимента.
6. Остановить таймер после сохранённого решения аналитика. Отдельно записать исключённые периоды ожидания и причину.
7. Два проверяющих независимо классифицируют спорные действия; расхождение разрешается до расчёта. Посчитать парные показатели и агрегаты.

## Контроль воспроизводимости

Карточка прогона содержит: `run_id`, хеш fixture, incident id, режим, analyst pseudonym, timestamps UTC, исключённые интервалы, `T`, `A`, версии TAKT/браузера/внешних систем и ссылку на audit ledger. Повторный расчёт из выгрузки должен давать те же значения. Секреты и персональные данные в материалы измерения не включаются.

## Ограничения

Результат не переносится на иной сценарий без повторного измерения. Ошибка либо незавершённое расследование не может считаться ускорением. Критические действия остаются human-in-the-loop.

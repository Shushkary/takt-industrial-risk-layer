# Вкладка «Симуляция»: цепочка атаки с объяснением обнаружения

## Назначение

Окно расследования ([analyst_window.md](analyst_window.md)) отвечает на вопрос «что в
кейсе». Симуляция отвечает на другой: **почему продукт отобрал именно это**. Для каждого
шага цепочки видно, каким механизмом ТАКТ его выделил и на каком основании — пивотом по
отличительной сущности, расширением разбора до уровня узла или срабатыванием инварианта.

Второе назначение — показать разницу в трудоёмкости разбора, не подменяя её обещаниями:
счётчики разделяют замер и расчёт и называют границы применимости прямо в интерфейсе.

Данные: `GET /cases/{id}/simulation`.

## Состав вкладки

| Блок | Что показывает | Источник |
|---|---|---|
| Трудоёмкость разбора | счётчики действий и модельного времени, сокращение действий | `effort` |
| За счёт чего сокращены действия | шаги модели ручного разбора и механизм, закрывающий каждый шаг | `effort.model_breakdown` |
| Плеер цепочки | шаги по времени, цвет по фазе, легенда | `steps`, `phases` |
| Ход цепочки | две оси одного дела: реальное время событий и шаги плеера подряд, цвет деления — фаза | `steps[].observed_at`, `steps[].attack_phase` |
| Граф атаки | сущности цепочки и переходы; показывается только при двух и более сущностях | `steps[].entities` |
| Итог разбора | класс риска, инварианты, варианты реагирования | `risk_class`, `invariants`, `response_options` |

Вершин на графе столько, сколько различных сущностей у событий дела, а не столько, сколько шагов в плеере. Дело, собранное пивотом по одному адресу, даёт одну вершину: в корпусе AIT (EXT-001) так выглядят все дела — адрес приходит и в `host_id`, и в `src_address`, и в `dst_address`, а второго участника источник не сообщает. Связывать в таком деле нечего, поэтому блок графа скрывается целиком, а ход дела показывает лента.

Лента строится по двум осям сразу. Одной оси реального времени мало: в `INC-AIT-001` 65 событий из 69 укладываются в шесть секунд, бегунок стоит на месте и последовательность шагов не читается. Одной оси шагов мало по обратной причине — из неё не виден темп: всплеск разведки, сорокаминутная пауза, одиночный выход на управляющий канал.

У каждого блока и каждого значения есть кнопка пояснения. Реестр — константа `HELP` в
`frontend/takt-pt-arm/app.js`, он же обслуживает окно расследования; параллельного механизма
подсказок нет.

## Фазы цепочки атаки

Перечень задан в домене (`takt.domain.entities.kill_chain`): разведка, первичный доступ,
выполнение, управляющий канал, эскалация привилегий, горизонтальное перемещение,
закрепление, эксфильтрация, воздействие.

**ТАКТ фазу не вычисляет.** Она приходит с разметкой источника или датасета в полях
`attack_phase` и `mitre_technique`. Событие без разметки остаётся в кейсе, но шагом цепочки
не считается — его количество показано отдельной строкой «Без разметки фазы». Приписывать
фазу самостоятельно означало бы выдавать предположение за факт.

На INC-002: 41 событие в кейсе, из них 27 шагов цепочки в семи фазах, 14 без разметки —
это события, добранные расширением до уровня узла.

## Методика счётчиков

Счётчики намеренно разнородны, и это указано в интерфейсе.

**Аналитик в ТАКТ — замер.** Источник: append-only журнал кейса с цепочкой хэшей. Ручным
считается действие с меткой `actor=`; автоматические операции конвейера её не имеют.
Опорная сессия воспроизводится `scripts/record_reference_session.py`, иначе число менялось
бы от прогона к прогону.

**Аналитик вручную — расчёт.** Модель с явными коэффициентами по составу кейса:

```
(источников) + (сущности × источники) + (сущности × (источники − 1)) + (события) + 1
```

**Сокращение** = (ручные − ТАКТ) / ручные × 100%. На INC-002: (88 − 9) / 88 = **89.8%**.

**Время — модельная оценка.** Коэффициент «секунд на действие» в
[методике](baseline_methodology.md) не задан и никем не измерялся, поэтому у эндпоинта
значения по умолчанию нет: без параметра `seconds_per_action` время не возвращается вовсе.

Во вкладке коэффициент задаёт оператор — поле «Секунд на одно действие» рядом со
счётчиками, начальное значение 20. Это объявленное допущение, а не величина из методики, и
так подписано в интерфейсе. Время пересчитывается при изменении поля.

Отдельного «сокращения времени» в интерфейсе нет намеренно: модельное время равно числу
действий, умноженному на коэффициент, поэтому его сокращение совпало бы с сокращением
действий и выглядело бы вторым независимым доказательством, которым не является.

Числовая характеристика производительности без ссылки на измерение запрещена
[границами продукта](../product_boundary.md).

Границы: журнал не отражает навигационные клики, поэтому число действий в ТАКТ — нижняя
граница, а сокращение — верхняя; в модели преобладает шаг «фиксация событий в заметке».
Расчёт не заменяет парный прогон с наблюдателем.

## За счёт чего сокращены действия

Счётчик отвечает «насколько меньше», но не отвечает «почему». Блок раскладывает модель
ручного разбора по шагам и напротив каждого называет механизм продукта, который этот шаг
закрывает:

| Шаг ручного разбора | Механизм ТАКТ |
|---|---|
| открыть консоли источников | единое окно: события четырёх классов источников приведены к одной модели при приёме |
| поиск сущностей по системам | один поиск по событиям всех источников; ядро дела собрано пивотом по отличительным сущностям |
| перенос идентификаторов между системами | идентификаторы сведены в деле, карточка сущности открывается кликом |
| фиксация событий в заметке | цепочку событий и журнал дела ведёт продукт, находка отмечается кнопкой |
| сведение итога | паспорт инцидента и сводку для руководителя собирает продукт |

Числа берутся из `effort.model_breakdown` и в интерфейсе не пересчитываются — иначе итог
блока разошёлся бы со счётчиками на той же странице. Соответствие «шаг — механизм» описывает
устройство продукта, от данных дела не зависит и потому живёт в интерфейсе
(`MANUAL_STEP_MECHANISM` в `app.js`). Шаг, которого нет в перечне соответствий, показывается
с прочерком; связность ключей с `ManualProcessModel` держит
`test_saved_actions_block_matches_the_manual_process_model`.

### Языковая модель

Кнопка «Роль языковой модели» открывает пояснение, отделяющее замысел от поставки.

**В продукте языковой модели нет.** Ни отдельного слоя `takt/ai`, ни маршрутов `/ai/*`, ни
признака включения в конфигурации: всё сокращение, показанное счётчиками, получено
детерминированными механизмами из таблицы выше. Вызовы моделей в домене и слое приложения
запрещены сторожем детерминизма
([`tests/test_verdict_determinism_guard.py`](../../tests/test_verdict_determinism_guard.py)).

**Где модель допустима.** Отдельным необязательным модулем вне контура вердикта — перевод
запроса на естественном языке в параметры обычного поиска и подсказка следующего шага
(Спринт 7 плана, опция). Условия допуска перечислены в
[границах продукта](../product_boundary.md), раздел «Где допустим ИИ-ассистент», и повторены
в самом пояснении: тот же результат достижим обычным фильтром, вывод помечен как
недоказательный и не входит в манифест, каждый вызов виден в журнале аудита, конфиденциальные
поля маскируются до отправки, при недоступности модели интерфейс возвращается к фильтрам.

**Клики модель не убирает.** Счётчик «Аналитик в ТАКТ» считает записи журнала с меткой
`actor=`, а не нажатия: навигация состояние дела не меняет и в журнал не попадает. Поэтому
числа кликов продукт не измеряет вовсе — об этом прямо говорит пояснение «Почему кликов
меньше» в окне расследования.

## Внешние цепочки атак

### AIT-ADS — подключён

| | |
|---|---|
| Датасет | AIT Alert Data Set: алерты AMiner и Wazuh на сценариях AIT Log Data Set V2.0 |
| Публикация | Zenodo, запись [8263181](https://zenodo.org/records/8263181) |
| Лицензия | **CC-BY-4.0** — производные допустимы при указании авторства |
| Конвертер | [`scripts/import_external_chains.py`](../../scripts/import_external_chains.py) |
| Результат | [`tests/fixtures/pt_techlab/ext_001/`](../../tests/fixtures/pt_techlab/ext_001/) |

Цитирование: Landauer, M., Skopik, F., Wurzenberger, M. (2024). *Introducing a New Alert
Data Set for Multi-Step Attack Analysis.* CSET 2024.

Уточнение по лицензиям: под GPL-3.0 распространяются **скрипты** репозитория
`ait-aecid/alert-data-set`, а не данные. Конвертер написан с нуля и читает опубликованные
данные напрямую, поэтому копилефт на репозиторий не распространяется.

Уточнение по формату: каталога `alerts_csv` из README проекта в опубликованном архиве нет —
он собирается их скриптами локально. Архив содержит построчный JSON выгрузок детекторов
(`<сценарий>_wazuh.json`, `<сценарий>_aminer.json`), конвертер читает именно их. Suricata
в этой записи Zenodo отсутствует, поэтому классов источников на выходе два.

Сырые датасеты в репозиторий не вносятся: 96 МБ в архиве, до 673 МБ на сценарий после
распаковки. Порядок воспроизведения — в
[README фикстуры](../../tests/fixtures/pt_techlab/ext_001/README_EXT-001.md).

### BOTS v3 — заготовка сопоставления

Датасет [`splunk/botsv3`](https://github.com/splunk/botsv3) (CC0-1.0, 320 МБ)
распространяется как **предындексированный Splunk**. Прямая конвертация без запуска Splunk
некорректна: индекс хранит сырые события вместе со схемой извлечения полей, и разбор
файлов индекса в обход движка даст неполные и неустойчивые результаты. В MVP датасет не
конвертируется.

Заготовка сопоставления на случай, когда появится экспорт через Splunk (`| export` или
REST-запрос к `search`):

| Индекс / sourcetype BOTS v3 | Класс источника ТАКТ | Ключевые поля |
|---|---|---|
| `WinEventLog:Security`, `Sysmon` | `edr` | `host`, `user`, `ProcessGuid`, `ParentProcessGuid`, `Hashes`, `Image` |
| `aws:cloudtrail`, `o365:management:activity` | `siem` | `eventName`, `userIdentity`, `sourceIPAddress` |
| `stream:http`, `stream:dns`, `suricata` | `ndr` | `src_ip`, `dest_ip`, `query`, `bytes` |
| `ms:o365:reporting:messagetrace` | `siem` | `SenderAddress`, `RecipientAddress`, `Subject` |

Фазы цепочки для BOTS v3 в датасете не размечены: ответы на вопросы соревнования известны,
но пофазной разметки событий нет. Без неё события попадут в кейс, но шагами цепочки не
станут — так же, как события INC-002 без разметки.

## Проверка

```powershell
# данные и кейс
python -m takt.tools.load_dataset --source netflow --path tests/fixtures/pt_techlab/inc_002/ndr.csv
python -m takt.tools.assemble_incident --case-id INC-002 --seed user:smirnov ...
python -m scripts.record_reference_session --case-id INC-002

# API
curl http://127.0.0.1:8090/cases/INC-002/simulation
```

Ожидается: `chain_length` 27, семь фаз, `effort.takt_actions` 9 против
`effort.current_actions` 88, `reduction_actions_percent` 89.8. Ноль в `takt_actions` и 100%
в сокращении означают пустой журнал дела: опорная сессия не воспроизведена, см.
[`scripts/record_reference_session.py`](../../scripts/record_reference_session.py).

Регрессии: [`tests/test_simulation.py`](../../tests/test_simulation.py),
[`tests/test_arm_simulation_tab.py`](../../tests/test_arm_simulation_tab.py),
[`tests/test_import_external_chains.py`](../../tests/test_import_external_chains.py).

# Матрица ролей SOC

Статус: реализация Спринта 3, 2026-07-11. Аутентификация — именованные ключи `TAKT_API_KEYS` в формате `key:actor_id:role`.

| Возможность / маршруты | analyst_l1 | analyst_l2 | manager | admin |
|---|:---:|:---:|:---:|:---:|
| Чтение кейсов, сущностей, событий, артефактов и находок (`GET`, `HEAD`) | ✓ | ✓ | ✓ | ✓ |
| Ingest, квалификация, решение по кейсу, находки и ручные артефакты | ✓ | ✓ | — | ✓ |
| Ручные `attach`/`detach`, `merge`/`split` | — | ✓ | — | ✓ |
| Пакеты реагирования и действия углублённого расследования | — | ✓ | — | ✓ |
| Отчёты и статистика на чтение | ✓ | ✓ | ✓ | ✓ |
| Импорт полного реестра, SIEM-forward, управление audit engagement | — | — | — | ✓ |

`manager` является read-only. Старые роли поддерживаются для обратной совместимости: `operator` эквивалентен `analyst_l2`, `auditor` — `manager`. Одиночный `TAKT_API_KEY` по-прежнему получает `admin`.

Неизвестный write-маршрут по умолчанию требует `analyst_l1`; это fail-closed относительно `manager`. Все новые критичные маршруты должны быть явно отнесены к L2 или admin в `rbac.py`.
